# control_center_joint_control

Autolife S2（306）全身关节状态监控、内置三维模型显示与安全调节工具。

## 功能

- 实时读取厂家全身反馈 JSON，显示 23 个关节的角度、速度、力矩、温度和通信状态。
- 操作界面直接解析 URDF/STL 并显示机器人实时三维姿态，不启动、不依赖 RViz2。
- 滑块调整时在内置视图中显示半透明目标虚影；真机解锁后，默认开启“拖动实时跟随”。
- 三维视图支持鼠标旋转、滚轮缩放、正视、侧视、视角复位和目标虚影开关。
- 三维视图提供“观察/调关节”双模式。“调关节”中点击机器人部位会高亮并选中对应关节，可直接横向拖动或用下方角度条精调；左侧会自动定位到同一关节。
- 取消“拖动实时跟随”后，滑块只预览，点击“发送本组”才控制真机。
- “发送本组”只改变当前页；其他身体分组沿用控制器既有目标，不会夹带其他页的预览值。
- 大幅拖动不会再被整组拒绝：桥接器接受最终目标，并以最多领先实测值 5°、10 Hz 的小步目标持续跟随。渐进命令只朝目标单向推进，不会被反馈噪声带着来回反向；进入身体关节 ±1° 容差后停止重复微调。
- 按头颈、左臂、右臂、腰腿、夹爪分组，支持中英文搜索、目标同步和单组发送。
- “腰腿”页新增“身体高度联动”：用一个 0～56 cm 滑块同步调整踝、膝和腰部俯仰，采用厂家 S2 的 `[76°, 155°, 81°]` 最大下降比例，让上身保持接近竖直；腰部旋转保持不动。界面同时显示当前和目标下降量。
- “姿态库”可把当前 23 个关节实测值保存到功能包中，支持内置三维预览、一键渐进执行和删除。
- 执行保存姿态前可在“姿态库”中选择 10%～200% 到达速度；默认 50%，200%对应约10°/次、理论100°/s，普通关节拖拽仍使用 100% 响应。
- “动作库”可把多个目标姿态编成关键帧动作，支持逐帧过渡时间、停留时间、缓动方式、顺序调整和循环执行。
- 动作可以先用三维半透明虚影完整预览，真机执行时可随时停止并保持停止时的实测姿态。
- 真机控制默认锁定；180 秒无操作自动锁定。
- 提供“解锁并复位”和“解锁（不复位）”两个入口；前者调用厂家正式复位/使能流程，后者只读确认位置模式、锁存当前实测姿态并同步使能全部身体关节，不发送复位、不改模式、不主动清错，从而避免使能过程中出现主动卸力窗口。
- 不复位解锁支持机械臂服务首次启动后的未使能状态；若检测到控制器不在位置模式则拒绝操作，避免危险切换。准备期间必须保持机器人姿态稳定，等待界面提示“可以控制真机关节”后再调节。
- 腰腿关节需要第二道高风险确认。
- 反馈超时或解锁期间检测到其他全身命令发布时自动锁定。
- 同一机器人只允许一个桥接器运行；误开第二次会整套退出，避免模型和数值在两套状态之间闪烁。
- 检查厂家/URDF 关节限位；所有目标都会先限制在各关节合法范围内。

## 启动

```bash
cd "/home/ubuntu/ros2_ws"
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=0
ros2 launch control_center_joint_control control_center_joint_control.launch.py
```

指定机器人编号或完整话题后缀：

```bash
ros2 launch control_center_joint_control control_center_joint_control.launch.py \
  robot_id:=307 topic_suffix:=0_307
```

只启动后台监控（不打开操作和三维图形界面）：

```bash
ros2 launch control_center_joint_control control_center_joint_control.launch.py \
  panel:=false
```

## 推荐操作顺序

1. 确认顶部显示“已连接 · 23/23 关节”。
2. 点击“全部同步当前值”。
3. 锁定状态下拖动滑块，先检查界面右侧的半透明目标虚影。
4. 确认环境安全后选择“解锁并复位”；若必须保持当前姿态，选择“解锁（不复位）”并等待位置模式检查、同步使能和姿态稳定检查完成。
5. 默认开启“拖动实时跟随”，此时拖动会实时控制当前分组；若取消该选项，则点击“发送本组”才会运动。
6. 操作完成后点击“立即锁定下发”。

腰腿动作可能改变机器人重心，只有在机器人稳定、周围清空且有人看护时才可二次解锁。

## 一键调节身体高度

1. 打开“腰腿（高风险）”页，确认“身体高度联动”显示了当前下降量。
2. 真机锁定时先拖动“降低”滑块；此时只更新踝、膝、腰部俯仰三个目标和右侧三维虚影，不会让机器人运动，腰部旋转保持实测位置。
3. 检查目标虚影和周围空间。需要真机跟随时，先完成真机解锁，再确认“腰腿二次解锁”和“拖动实时跟随”均已开启。
4. 缓慢调节滑块。取消“拖动实时跟随”时，可先设定高度，再按“发送本组”。“标准高度”按钮会把三个联动关节恢复到标准目标。

联动目标沿用本工具原有的渐进跟随、限位、反馈超时和180秒自动锁定保护。踝、膝、腰部俯仰共用一个运动进度，因此会同时起步并同步到达。最大56 cm是厂家脚本提供的机械范围，不表示任何场景都适合降到最低；机器人负载较大或周围有人时应使用较小步幅。手动单独调整三个联动关节后，界面会标记为“约”降低值；再次拖动高度滑块会重新回到标准联动比例。

从降低后的高度执行姿态库“默认”或其他符合高度联动曲线的姿态时，桥接器会自动识别并继续使用三轴同步轨迹返回，避免普通等角度步长造成膝关节落后、机器人暂时或最终后仰。姿态包含明显的腰部旋转变化时不会自动套用高度模式，以保证保存的腰部旋转仍可正常恢复。

## 在三维模型上调节关节

1. 点击三维视图顶部的“调关节”。
2. 点击机器人手臂、头颈、腰腿等部位；选中的部位会显示为橙色，左侧自动切换到对应分组。
3. 按住选中部位并横向拖动，或使用视图下方的角度条和数字框精调。
4. 点击“同步当前”可撤销该关节的预览变化。
5. 点击“观察”返回旋转、缩放视角模式。

模型调节与左侧滑块共用同一条安全控制链：锁定时只改变目标虚影；解锁并开启实时跟随后才控制真机；腰腿仍必须二次解锁。夹爪反馈是电机转角，无法可靠映射为手指模型角度，因此三维模型不直接调夹爪，仍需使用“夹爪”页。

## 创建和执行关键帧动作

1. 先在关节页或三维模型里调整目标，再打开“动作库”。新动作会自动选择刚才编辑的身体分组，也可在第一帧前手动多选；界面会明确显示“下一帧将记录”的组。添加首帧后分组会锁定，避免不同帧关节集合不一致。
2. 在关节调节页或三维模型中摆好目标，点击“添加当前目标”。这里保存的是界面目标值，方便先在锁定状态下编排，不要求真机已经到达。
3. 继续调整姿态并添加关键帧；每帧可设置到达该帧的过渡时间、到达后的停留时间，以及“平滑”或“线性”插值。与上一帧完全相同的重复帧会被拒绝，并提示当前实际记录的关节组。
4. 可复制、替换、删除或上下移动选中的关键帧，并设置整个动作的循环次数。“复制帧”会把副本插到原帧后面并自动选中，适合复制后只修改一个关节制作往复动作。
5. “真机执行速度”可在10%～200%之间调节并随动作保存。100%对应约5°/次、10Hz的渐进上限；200%对应约10°/次、理论100°/s。速度会缩放关键帧过渡时间并限制渐进命令速度，停留时间保持不变。
6. 点击“三维虚影预览”检查完整动作。预览只驱动半透明模型，不控制真机。
7. 输入动作名称并保存。软件会同时更新动作YAML，并在 `action_pkls/` 生成与厂家录制轨迹兼容的同名PKL文件。
8. 真机执行前确认反馈在线、先解锁真机控制；动作包含腰腿时还要完成腰腿二次解锁。点击“真机执行”并确认后开始，必要时点击“立即停止动作”。

每帧“到达时间”是期望过渡时间，不是强制跳帧期限。时间结束但真机尚未进入目标容差时，界面会显示“等待实际到达”并继续跟随；只有连续30秒没有任何有效进展，或超过按关节角度和速度动态计算的宽限上限才停止。动作执行期间，普通滑块命令会被拒绝，避免两种目标互相覆盖。停止、反馈超时、自动锁定或通信异常时，动作执行器会中止后续关键帧；手动停止还会把控制器目标保持在当时的实测关节位置。

## 保存和调用全身姿态

1. 打开“姿态库”页，输入名称，点击“保存当前全身姿态”。保存的是机器人当前实测值，不是滑块预览值。
2. 选中姿态后点击“在三维视图预览”，此操作不会控制真机。
3. 需要真机到达时，先解锁真机控制，再点击“让机器人到达”并确认。
4. 执行前可用“到达速度”滑块选择 10%～200%；较低比例会缩小、超过100%会放大每次渐进下发的目标步幅。
5. 如果该姿态需要改变腰腿，必须先勾选“腰腿二次解锁”。

姿态保存在功能包源码目录的 `motion_library/saved_joint_poses.yaml`。调用时各关节使用与拖动控制相同的渐进跟随机制；反馈断开、自动锁定或检测到其他全身控制命令时会立即停止继续下发。

“到达速度”是本工具对渐进目标步幅的比例调节，不是厂家电机内部的精确角速度闭环；实际速度还会受到机器人负载和底层控制器限制。

## 动作与姿态文件

源码功能包内统一保存目录：

```text
motion_library/
├── saved_joint_actions.yaml
├── saved_joint_poses.yaml
└── action_pkls/
    └── <动作名称>.pkl
```

每次保存或覆盖动作，YAML和同名PKL会一起更新；删除动作时同名PKL也会删除。PKL参照 `shake_hand_example.pkl`，使用Python pickle协议5，顶层为 `list[tuple[float, str]]`：元组第一项是相对时间，第二项是包含全身状态及目标数组的厂家JSON字符串。关键帧按照动作速度、平滑方式、停留和循环次数展开为约100Hz的密集轨迹，未参与动作的关节使用保存动作时的全身实测姿态。

其他功能包只应读取可信来源的PKL；Python pickle不是安全的数据交换格式，不要加载未知或外部下载的文件。

## 主要 ROS 接口

- `/control_center_joint_control/joint_states`：实时模型关节状态（弧度）。
- `/control_center_joint_control/target_joint_states`：目标虚影关节状态（弧度）。
- `/control_center_joint_control/status`：面板所用的完整状态 JSON。
- `/control_center_joint_control/set_hardware_enabled`：解锁并执行厂家复位，传 `false` 时锁定。
- `/control_center_joint_control/set_hardware_enabled_without_reset`：不发送复位命令直接解锁，传 `false` 时锁定。
- `/control_center_joint_control/set_leg_waist_enabled`：腰腿下发二次开关。
- `/control_center_joint_control/action_command`：面板发送的关键帧动作执行/停止命令。

夹爪厂家反馈是 10–360° 的电机转角，并不是 URDF 中腕部到工具的旋转关节，因此面板显示真实电机角，模型中的该关节保持中位。这避免了把电机角错误映射成工具姿态。
